opthub · how it works

Is the cheaper setting doing the same job?

opthub takes a real coding-agent session, picks cheaper settings for it, runs the same task again under each setting in a sandbox, and has a second model grade the results without knowing which is which. Pick a session and how the settings are chosen, then play it.

    The five steps

    1. Inspect. Read the transcript Claude Code already left on disk: how many requests, how big the context got, which model and effort, how much of the output was thinking. Nothing is sent anywhere.
    2. Classify. Work out where the money went (re-reading context, writing it, output, thinking) and how much each lever could take off this session. Every estimate is labelled: priced, guess or detector.
    3. Decide. Choose the settings to try. The best preset is the same for every session. Dynamic settings are picked from this session's own numbers: a one-file fix gets a small model, a long investigation keeps the big one.
    4. Verify. Run the session's prompts again from the same starting code, once per setting, three times each, in a sandbox with no credentials of its own. A second model scores the code changes blind, twice with the order swapped.
    5. Compare. Each cheaper setting is compared with the baseline replay, never with the original session. It wins only if it costs less and quality and finished work are no worse. Below three repeats there is no verdict.

    What the result guarantees

    • A setting that is cheaper and worse is reported as cheaper and worse.
    • The grader never sees which setting, model or cost produced a change.
    • Every replay is a new session you can open and inspect like any other.
    • Prompts, diffs and paths stay on your machine.
    • Nothing that spends money starts without --yes.
