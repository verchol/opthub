A measurement rig for coding-agent efficiency

Harness Economics

Every comparison of coding agents compares models — the one variable a team doesn't control. This measures the one they do: the harness around the model. Same task, same model, two cloud machines, one difference.

The lever nobody measures

Agent spend is becoming a real line item, and the instinct is to manage it by picking a cheaper model. But the largest published account of running agents at scale says the savings came from somewhere else: how work is packaged before the model ever sees it. Uber reported these over six months, holding capability flat.

34%lower cost per 1,000 requests, model held fixed
52%lower cost per session from its June peak
9.4×growth in weekly agentic requests over the same window
70%of pull requests attributed to local or cloud agents

Uber, Building an Efficient Software Factory, Feb–Aug 2026.

Those are the numbers of a team that instrumented its harness. The techniques are published; what isn't published is a way to tell whether any of them help you, on your code, before you commit engineering time to them. That is the gap this fills.

What the rig does

  1. Boots two identical cloud microVMs.Same base image, same CPU and memory, booted in parallel — roughly a second each.
  2. Gives both the same task and the same model.A specification with unambiguous, mechanically checkable requirements. Nothing about the model varies, so nothing measured is attributable to it.
  3. Changes exactly one thing in the second machine.An optimization strategy, defined in a single file. Whatever it doesn't set stays at the control's value.
  4. Grades both with a test suite neither could see.Written into each machine only after the agent process exits. No run can be tuned against its own scorer.
  5. Reports cost against outcome.Not tokens burned — cost per passing test. Spend denominated in work that actually landed.

The grader was validated at 47/47 against a reference implementation before any run happened. That matters more than it sounds: it proves the tests are winnable and the specification is unambiguous, so a low score is a real failure rather than a rigged one.

An idea becomes an experiment in four lines

This is the whole interface. No code, no configuration schema, no rebuild — a description and an instruction, saved as a file. The system appends it to the task prompt the control also receives, so for a strategy like this one, that paragraph is the entire difference between the two machines.

--- experiments/plan-first.md
description: Force an explicit behaviour checklist before any code is written.

Before you write a single line, write PLAN.md containing a numbered
checklist of every distinct behaviour the spec requires — every value
rule, every error type and the exact condition that triggers it.

More elaborate strategies add flags, drop scaffolding files into the workspace, or introduce a reviewer agent on a cheaper model that gates completion. Six ship with the rig, spanning a single flag through a full stack of techniques.

Where this stands

  • ✓Infrastructure proven end to end — VMs boot in ~1s, agent tooling installs in ~6s
  • ✓Benchmark and 47-test hidden grader built and validated at 47/47
  • ✓Six optimization strategies defined and loading
  • ✓Comparison report and chart generating
  • —No comparison has been run yet. There are no results.

Stated plainly because the alternative is worse. When results do arrive they will be n=1 per arm, and agent runs vary substantially between passes — the shape of a difference, not a defensible figure, until three repeats say otherwise. The optimized arm is expected to win on cost; that is the hypothesis under test, not a finding.

Why it generalizes

Nothing in the machinery is specific to the sample task. The specification, the grader, and the strategy files are all swappable inputs. Point it at a task from your own codebase with a real test suite, and the same apparatus answers the same question: does this way of working actually pay for itself here — before anyone spends a quarter rolling it out.

The model is deliberately held constant throughout. Model routing was the single largest lever in the published account, and it is excluded here precisely so that everything measured belongs to the harness.
