# opthub

Measures whether a cheaper way of running a coding agent does the same job, by replaying real
Claude Code sessions and grading them blind. This repo is self-contained: the spec, the measurements,
the read-only Python analysis tools, the runnable implementation (`app/`: the `opt` CLI, the hub, the
experiment loop) and the sandbox providers it runs arms in (`sandbox/`). Nothing points outside the
checkout; `node sandbox/test.mjs` checks that.

What spends money: `tools/rerun.py run|judge|go` (refuses without `--yes`); in `app/`, every command
that starts an arm (`opt demo run`, `opt run`, `opt replay`, `opt optimize`, `opt claude -p|example|optimize`)
and the hub's run endpoints (`/api/optimize`, `/api/experiment`, `/api/triage/*`). Never trigger those
when testing.

## Layout

- `SPEC.md` — the spec, versioned (currently **v0.4**). §2 lists what v0.1 claimed that measurement killed.
- `PROGRESS.md` — dated log, newest **last**. Add an entry when a measurement changes a claim.
- `README.md` — front door and roadmap.
- `docs/` — `experiments.md` (E1/E1b), `optimizers.md` + `optimizers-cookbook.md` (levers),
  `router-comparison.md`, `local-inference-capacity.md` (when a local Ollama route is safe),
  `optimization-agent.md` ([O] agent design: optimization models → skills → action tools, deep context),
  `dynamic-config-analysis.md` (per-session Claude Code config savings, from `tools/dynconfig.py`), `demo-mock-spec.md` (four-terminal demo, source of all demo numbers),
  `demo-thesis.md` + `demo-diagrams.md` (developer demo), `ARTIFACTS.md` (shared-page index).
- `docs/data/` — pinned ledgers `e1-sessions.csv` (215 sessions) and `e1b-sessions.csv`
  (214 sessions, $508.80). Prompts and absolute paths are stripped; keep it that way.
- `docs/screens/` — hub screenshots (`INDEX.md`) and rendered demo diagrams (`diagrams/`).
- `tools/` — stdlib Python, read-only: `sessions.py`, `lenops.py`, `loopscan.py`, `savings.py`,
  `costmodel.py`, `ctxwatch.py`. They are the source of every number in `docs/`, and all price with
  `ratecard.py` (one versioned rate card; `ratecard.py check` compares it with Claude Code's own cost records).
  `rerun.py` is the exception: it replays a session's prompts as new sessions with new flags
  (baseline arm vs goal arm), judges the diffs blind, and writes a radar report to `data/private/reruns/`.
  Arms run in the local Docker sandbox by default (`sandbox/docker/`, not E2B); `--sandbox host` opts out.
  `dynconfig.py` prices every lever of the Claude Code config catalog per session, marginal in applied
  order, counting usage once per request (transcripts repeat it per content block).
  `tune.py` picks a session's "dynamic" flags from its own numbers; `rerun.py plan --dynamic` adds them as a
  third arm beside the goal's fixed "best" preset. `readscan.py` finds large whole-file reads and prices
  what the `bulk-read-delegation` lever (hooks in `app/hooks/bulk-read/`) could take off, as a ceiling. `envfile.py` loads secrets from `.env` (template `.env.example`).
  The onboarding scan (`docs/onboarding-spec.md`): `onboard.py` runs P0–P5 over `onboardlib.py`'s loader —
  `cachestatus.py` (P1), `probe_cache.py` (P2, the only one that spends; `--yes`), `gapscan.py` (P3),
  `savings.py --classes` (P4), `sessiongraph.py` (P5) — and writes findings to `data/private/onboard/<date>/`.
- `examples/golden/` — synthetic sessions run through all five steps; `expected/` is the golden output,
  `how-it-works.html` is generated by `demo.py` from `how-it-works.template.html`. Offline numbers are
  simulated: never quote them.
- `experiments/` — J-series classifier experiments (`email-triage` = J2, `session-triage` = J3, Jev).
- `app/` — the implementation, Node (ESM `.mjs`, no build step except the page): `opt.mjs` (CLI),
  `hub.mjs` (Optimization Hub, serves the React app built from `app/web/` into `app/web/dist`), `lib/`,
  `lib/ult/` (the `opt claude optimize` router), `config/`, `tasks/`, `scenarios/`, `test/`.
  It finds the Python side through `REPO_ROOT` in `app/lib/state.mjs`. Run state (`app/results/`,
  `app/audit/`, `app/claude-profile/`, …) is gitignored; `OPT_HOME` moves it.
- `sandbox/` — the providers, one directory each: `docker/` (local, shared with `tools/rerun.py`) and
  `e2b/` (cloud microVMs and their templates). Only `sandbox/e2b/index.mjs` loads the E2B SDK; a provider
  never imports `app/`. See `sandbox/README.md`.
- `package.json`, `opt` — one install at the root (`npm install`; `e2b` is optional), and the CLI
  launcher (`ln -s "$PWD/opt" ~/.local/bin/opt`). One `.env` at the root for Node and Python alike.

## Commands

The full list, with what spends money: `docs/commands.md`. The everyday ones:

```sh
python3 tools/lenops.py view                 # session ops report (also /lenops)
python3 tools/savings.py --days 30           # per-session lever headroom
python3 tools/costmodel.py                   # run before editing any number in docs/optimizers.md
python3 tools/rerun.py plan <session-id> --goal cost   # free; then run/judge --yes, then report
python3 tools/tune.py <session-id>           # dynamic flags for one session (free)
python3 tools/dynconfig.py                   # per-session config savings over every transcript (free)
python3 tools/ratecard.py check              # the rate card vs Claude Code's own per-model costs (free)
python3 tools/onboard.py                     # day-0 onboarding scan, P0-P5 (free; --dry prints what would leave)
python3 -m unittest tools/test_onboard.py    # the probes' fixtures: known answers, silent cases, no text out
python3 tools/readscan.py --days 30          # large reads and the bulk-read ceiling (free); tests: tools/test_readscan.py
python3 examples/golden/demo.py --check      # golden test of the whole pipeline; --update after a deliberate change
python3 tools/envfile.py check               # which secrets are set, from shell or .env
cd experiments/session-triage && python3 src/run.py          # rules arm, pinned ledger, no egress
mmdc -i docs/demo-diagrams.md -o docs/screens/diagrams/demo.png -b white -s 2   # re-render diagrams
npm install && npm run build:web             # once per checkout: the app's deps and the hub page
npm test                                     # the app's checks and the sandbox boundary
./opt hub start                              # the Optimization Hub on :8899 (opt hub demo: the Tallyfox demo on :8950)
```

Three test suites: the golden check (Python stdlib only, and `mmdc` for diagrams), `npm test` (the app,
plus `sandbox/test.mjs`; no network beyond 127.0.0.1, no Docker, no model calls) and
`tools/test_onboard.py` (the onboarding probes on synthetic transcripts and a simulated API). After a change under
`app/web/`, `npm run build:web`.

## Rules for numbers

- **Every figure comes from a tool or a pinned file.** Never type a number into a doc that a
  script did not produce; cite the source.
- **Label every saving estimate**: `priced` (tokens re-priced at list rates — a ceiling),
  `guess` (stated basis, no measurement), `detector` (measured, and it says no), or measured.
- **Attribution is marginal, in applied order** (SPEC R1). Never quote a standalone saving as if
  it stacks.
- **Arms are compared to each other, never to the original session.**
- **n = 1 is not a finding.** Say so when quoting a single run; three repeats is the minimum.
- Cache-priming is a **detector** (hit rate 96.8%), not a lever. `context-lifecycle` is the top lever.
- Demo numbers live in `docs/demo-mock-spec.md` §5 — change them there first, then everywhere else.

## Privacy

- Session transcripts (`~/.claude/projects`) contain prompts and paths. Anything derived from live
  sessions goes to a gitignored `data/private/`; only stripped, pinned CSVs are committed.
- Nothing sent to an external classifier (Jev) may contain cost, paths, or prompt text — booleans
  and counts only.

## Git

- Branch `public` tracks `origin/main` (https://github.com/verchol/opthub). The repo is **public**:
